# SurrealKB 登录跳板小程序

核心职责：**被电脑网页的二维码扫进来 → 把登录票据交给后端 → 网页完成登录**。
不认证、不发布到搜索，不提供内容服务。

## 页面结构

| 页面 | 作用 |
|---|---|
| `pages/home/index` | **启动页**。服务说明 + 使用指引 + 协议入口 + 备案号位。任何人直接打开小程序都会看到这个完整可用的页面 |
| `pages/login/index` | 扫小程序码进入时的登录确认页（靠 `scene` 定位登录请求） |
| `pages/privacy/index` | 用户隐私保护指引 |
| `pages/agreement/index` | 用户服务协议 |

> 为什么需要 `pages/home`：审核人员直接打开小程序时**不带 `scene`**，如果只有登录页就会看到
> 「请从电脑网页扫码进入」这样的死胡同，容易被判「功能不完整」而驳回。
> 现在无 `scene` 时会自动转到首页，任何入口打开都有完整内容可看。

## 为什么用小程序而不是微信网站应用

微信开放平台「网站应用」扫码登录要求**企业/个体工商户营业执照 + 300 元认证 + 已备案域名**，
个人主体在后台里根本没有申请入口。小程序**个人实名即可注册、0 元**，是个人开发者的唯一正规解。

## 使用步骤（详见项目根目录的配置指南）

1. 去 [微信公众平台](https://mp.weixin.qq.com/) 注册**个人小程序**（实名 + 微信扫码验证，0 元）
2. 小程序后台 →「开发 → 开发管理 → 开发设置」拿到 **AppID / AppSecret**，填到后端 `backend/.env`：
   ```
   WX_MP_APP_ID=wx..........
   WX_MP_APP_SECRET=..........
   ```
3. 改本目录 `config.js` 里的 `API_BASE` 为你的后端地址（必须 https）
4. 用[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)导入本目录
   （`project.config.json` 里的 `appid` 已填为 `wx4a035f276ca9118b`）
5. 上传 → 提交审核 → 发布（**必须发布**，`getwxacodeunlimit` 生成的码指向正式版）
6. 小程序后台配好 **request 合法域名**（= 你的后端域名，要求已备案）

## 本地调试（不用真机扫码）

微信开发者工具 →「普通编译」下拉 →「添加编译模式」：

| 场景 | 启动页面 | 启动参数 |
|---|---|---|
| 模拟「扫码进来」 | `pages/login/index` | `scene=任意32位字符串` |
| 模拟「直接打开」（审核员视角） | `pages/home/index` | 留空 |

配合后端 `/api/auth/wx/qrcode` 返回的真实票据即可全链路自测。

## 提交审核前必做

1. `config.js` 填上 `CONTACT_EMAIL`（协议页会展示），备案号下来后再填 `ICP_NUMBER`。
2. 后台「设置 → 服务内容声明 → 用户隐私保护指引」配置并提交（提交代码审核的前置项）。
3. 用上面的「审核员视角」编译模式确认首页完整可用。
4. 详细材料模板见项目根目录 `SurrealKB_小程序提交审核材料模板_20261015.md`。

## 两个必须知道的坑

- **`scene` 必须是全局唯一随机值**：重复会导致两个用户登录进同一个账号。后端已用
  `secrets.token_hex(16)` 生成（正好 32 字符，卡在微信上限）。
- **域名白名单**：小程序 `wx.request` 的域名必须 https 且已备案。
  若还没备案，可用微信云开发的云函数做中转（云函数在服务端发起请求，不受该白名单约束）。
